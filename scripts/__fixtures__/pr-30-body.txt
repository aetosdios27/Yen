## What this does

The private ID people can read out over the phone: nine digits in groups of three, e.g. `482 739 105`, always shown next to the person's name. New package `@yen/identity` plus migration `0006_yen_ids.sql`.

- **Check digit:** the Damm algorithm over the first eight digits. It catches every single-digit error and every adjacent swap, so a mistyped ID is rejected before any lookup. The quasigroup table and the worked example (572 gives check digit 4) are checked in tests, and the two cited sources were opened: Damm's 2004 Marburg dissertation, and the 2007 paper in Discrete Mathematics 307, pp. 715 to 729.
- **Format:** random via `crypto.randomInt`, first digit 1 to 9 so a spreadsheet cannot drop it. Parsing accepts spaces, dashes and Devanagari digits, and never letters.
- **Storage:** `yen_ids` belongs to the account, one per user. `ON DELETE SET NULL` leaves a tombstone row when a user is erased, so a number is never re-issued. `assignYenId` is idempotent and race-safe, with collision retry.
- **Lookup** for "add by Yen ID": parses and checks the digit first, so a bad ID never touches the database or the limiter. It then needs a rate-limit token and returns only a masked name (`R**** P****`) or null.
