# Outbound dependency resilience

`@yen/shared` exports `ResilientCall`, a reusable timeout, bounded retry, and circuit-breaker wrapper. Retries use exponential backoff with full jitter. After the reset interval, one caller may make a half-open probe; success closes the breaker and failure reopens it. Tests can inject the clock, random source, and sleep function.

The wrapper counts one failed call after its configured attempts are exhausted. Breaker state is process-local. The shared unit tests cover timeout behavior, retry caps, and open, half-open, and close transitions. ClamAV and anchoring have their own client-level tests.

The anchoring policy covers every `RootChain` call, including `getBalance` and root checks in reconciliation and the recovery path. The CLI creates one `ResilientCall` and shares it between the anchoring worker and reconciliation hook. Its `AnchorAlertSink` also emits stale-anchor, root-mismatch, and low-wallet-balance alerts. The CLI selects `KmsRootSigner` when `ANCHOR_KMS_KEY_ID` is set and uses the signer account as the publisher address for balance alerts. Confirmation records `confirmed_at`; fee replacement uses the persisted pending transaction and a single broadcast attempt.

Retries are safe only for idempotent operations or operations protected by a stable idempotency key. Chain reads are retried; `publish` uses one attempt because a timeout cannot tell whether the chain accepted the transaction. The durable anchor lets the next worker run check the published root before submitting again. Messaging retries require the provider to honor the key; a local worker lease alone cannot guarantee exactly-once external effects.

## Reuse

Construct one `ResilientCall` per dependency and reuse it across calls so breaker state persists. Pass `now`, `random`, and `sleep` in tests for deterministic timing and backoff.


## Verification and external delivery limits

`packages/shared/src/resilience.test.ts` tests timeout and attempt caps, capped exponential backoff with full jitter, and breaker cooldown/probe recovery. The WhatsApp Cloud and Exotel local HTTP contract suites each test timeout, a single request on HTTP errors, and suppression of the sixth request after five failed sends. These are deliberately one-attempt policies: enabling jittered retries for ambiguous sends without vendor deduplication could send a notification twice.

The real Postgres SIGKILL and chain outage tests live in `packages/ledger/src/chaos.randomized.test.ts`. Sending rows with an unknown provider outcome are durably dead-lettered for reconciliation, not automatically retried. Exactly-once eventual external delivery remains unproven until the provider supports a stable idempotency key or a reconciliation protocol. The partner API row above is a proposed policy only; `UnconfiguredPayoutAdapter` fails closed and `ReferencePayoutAdapter` is a development stub, not an outbound HTTP integration.
