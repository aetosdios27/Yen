# DLT and WhatsApp registered templates

Yen sends transactional notifications and login OTPs to Indian residents. Under the TRAI Telecommunication Commercial Communications Customer Preference Regulations (TCCCPR), 2018, every transactional SMS dispatch must go through a DLT-registered entity with a registered sender header and a registered template ID. WhatsApp sends must use Business Solution Provider (BSP) approved templates with an explicit language code. This document is the source of truth for the exact registered template copy, categories, and variable mappings. The runtime enforcement lives in `packages/notifications/src/compliance.ts` and fails closed: a dispatch without the required regulatory identifiers or with unapproved variables is rejected before it reaches any provider.

## Registered identifiers

The following identifiers are placeholders. They are filled in during onboarding, after the DLT portal issues them and after Meta approves the templates. The registries in `packages/notifications/src/compliance.ts` keep the SMS template ID empty until then and reject SMS dispatches with a `template_registration_incomplete` violation, so no send is possible before registration is complete.

| Identifier                        | Configured in              | Value                                    |
| --------------------------------- | -------------------------- | ---------------------------------------- |
| DLT entity ID                     | `EXOTEL_DLT_ENTITY_ID`     | `TO_BE_FILLED_AFTER_DLT_ENTITY_APPROVAL` |
| DLT sender header (transactional) | `EXOTEL_SENDER_ID`         | `TO_BE_FILLED_AFTER_HEADER_APPROVAL`     |
| WhatsApp Business Account ID      | WhatsApp BSP console       | `TO_BE_FILLED_AFTER_BSP_ONBOARDING`      |
| WhatsApp sender phone number ID   | `WHATSAPP_PHONE_NUMBER_ID` | `TO_BE_FILLED_AFTER_BSP_ONBOARDING`      |

## Variable formatting rules

| Variable        | Source                                              | Format                                                 |
| --------------- | --------------------------------------------------- | ------------------------------------------------------ |
| `code`          | Login OTP generated by the identity service         | Six digit numeric code, no separators                  |
| `expense_title` | Expense record title                                | Plain text, no newlines                                |
| `amount_inr`    | Amount in paise from the notification template data | Indian Rupee decimal string, for example `Rs 1,250.00` |
| `fund_title`    | Fund record title                                   | Plain text, no newlines                                |

Variable values must never contain template placeholder syntax (`{#...#}` or `{{...}}`) and must not be used to smuggle links into a template whose approved body has none. The compliance validator rejects any variable name outside the registered set.

## SMS DLT templates

SMS delivery uses the Exotel gateway. The registered body uses DLT placeholder syntax `{#name#}`. Only the login OTP is delivered over SMS in this track; the remaining notifications are WhatsApp only. English and Hindi variants would each require a separate DLT registration; only English is registered here.

### `otp` (login OTP code)

| Attribute          | Value                                      |
| ------------------ | ------------------------------------------ |
| Channel            | SMS (DLT transactional)                    |
| Communication type | Transactional                              |
| Language           | English                                    |
| DLT template ID    | `TO_BE_FILLED_AFTER_DLT_TEMPLATE_APPROVAL` |

Registered body, character for character:

```
Your Yen club treasury login code is {#code#}. It is valid for 10 minutes. Do not share this code.
```

| Placeholder | Variable | Required |
| ----------- | -------- | -------- |
| `{#code#}`  | `code`   | Yes      |

The registered body uses Meta positional placeholders; the variable names list in the registry maps each positional placeholder to a named parameter in order. ## Enforcement

`packages/notifications/src/compliance.ts` exports two validators used before any dispatch leaves the system.

- `validateSmsDispatch` requires a numeric DLT entity ID, a six character transactional sender header, and a DLT template ID that matches the registered ID for the template key. It rejects unknown template keys, templates whose registration is incomplete, and any variable outside the registered set.
- `validateWhatsAppDispatch` requires the approved template name and an approved language code for the template key. It rejects unknown template keys and any variable outside the registered set.
- `buildSmsDispatchEnvelope` and `buildWhatsAppTemplatePayload` combine validation with rendering and return the dispatch envelope or the Cloud API payload only when the dispatch is compliant.

A dispatch that fails validation is never sent and never retried against a different channel. Changing a registered body, adding a variable, or adding a language requires a new registration or approval first, then a matching change to the registry in `packages/notifications/src/compliance.ts` and to this document in the same change.
